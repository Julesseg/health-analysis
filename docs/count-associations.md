# Stored count associations

A count recorded in the daily log can be selected as an input, an adjustment, or an output. A count input compares one additional event in the complete preceding local day. A manual count output uses completed local days and is available without a Health read. Its input window ends at the start of the output day. Count questions support a shorter analysis period and use the complete preceding-day behavior window. A day before a variable becomes applicable has no value. An explicit zero, an unreviewed default, and a confirmed default retain their stored value and origin. Confirmed defaults keep their effective date. Results count days using defaults in either role and allow inspection of paired count values and their origin.

For an imported resting heart rate or sleep duration output, the existing linear fit reports bpm or minutes per additional event, with the other modeled inputs held fixed. A count output uses Poisson pseudo-maximum likelihood with an intercept and a log link for the expected daily count. The model fits all selected inputs and adjustments together. A coefficient for an increment Δ is displayed as a proportional change of exp(βΔ) − 1. For example, 50% per additional event means the model estimates 1.5 times the expected daily count. A quantity adjustment still uses the normal 100 mg or one-unit increment. The fitted value describes an association within the observed history. Interactions involving counts are unavailable.

## Uncertainty and evidence

The fit solves the Poisson score equations with a scaled design and backtracking Newton updates. It permits zeros in the response and uses a robust score covariance, so it can represent extra-Poisson variation in the conditions validated here. The nominal 95% intervals use the calendar-day Bartlett HAC procedure and critical-value approximation also used for [adjusted numeric associations](adjusted-numeric-associations.md). The maximum lag is the greater of seven calendar days and twice the cube root of the paired count rounded up. The model transforms both limits from the log scale into proportional changes. These are individual contrast intervals. They describe neither the range of individual daily counts nor the probability of causation. See [Poisson pseudo-maximum likelihood](https://personal.lse.ac.uk/TENREYRO/LGW.html) and [separation in Poisson regression](https://repository.essex.ac.uk/3535/).

- Require at least 42 joint days and 12 per fitted parameter, including the intercept.
- Require at least six days outside the most common count for each count input, both among paired values and among paired recorded values. Quantities retain their numeric variation checks.
- A count outcome needs at least 12 recorded days, six recorded positive days, and six recorded days outside its most common count. Defaults are included in the fit after these support checks. Constant recorded counts, defaults alone, and sparse variation can each withhold the estimate.
- The existing design and variance-inflation checks detect collinear inputs. Fits with inadequate numerical information, separation, or unusable intervals are withheld. This is a guard against unstable estimates, with no general separation classification.
- A usable count estimate has low confidence. Coverage, frequent defaults, short history, uncertain direction, possible unmeasured influences, and finite lag coverage constrain interpretation. There is no calibrated practical near-zero band for daily count changes.

## Validation and extension

Application-boundary checks cover a reopened log with known 2× and 3× adjusted means, genuine zeros, default lineage after review, saved refresh without Health access, constant and separated outputs, and a count input with a known 2 bpm difference per event. The interval simulation uses 72 trials per scenario and 336 days per trial, alternating a null association and a 1.45× per-event mean. An independent or persistent two-state multiplier changes the daily Poisson mean. The persistent scenario uses a lag-one state correlation of 0.8. The checks bound empirical coverage, mean bias, and relative interval width. These checks cover the selected one-day scenarios. Longer windows, sustained trends, extreme sparsity, and confidence calibration beyond low remain unvalidated.

`AnalysisSeriesID.manualTyped` preserves the stored variable ID. `analysisVariables` provides typed definitions and supported roles. The store adapter resolves persisted values and origins, the dataset carries the raw typed samples, and the selected output kind determines the estimator. New variable types can add encoding, support checks, model choice, and effect rendering at those seams. Count estimates carry `proportionalCountChange` so presentation code can interpret their fractions and intervals. The new payload fields decode as optional for older results. Preserve the compatibility checks and raw values when combining this work with temporal windows, interactions, and evidence drill-down.
